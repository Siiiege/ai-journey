# AI 转型 · 第一阶段计划（12 周）

> 定位：在职前端开发者 → AI 应用工程师（AI 全栈方向）
> 每周预算：8~10 小时。W1–2 原理与实现 6~8h、复盘 2h；W3 起原理与实验 4~6h、应用 3h、复盘 1h。课程观看计入预算。
> 阶段完成标志：2 个精简手写实现 + 1 个可运行的小应用 + 1 份有结论的改进实验报告 + 3 篇长笔记（可直接作为项目说明，不额外重复写博客）。
> 2026-10-30 调整：原理与应用并行；微调按证据决定；周次是学习单元，不代表已完成或固定日历进度。

## 执行规则

- 核心验收未通过不能标完成；每两周复盘，优先删除选学项、缩小数据量和模型规模。
- 同一难点连续卡住两周：记录问题与最小复现，拆出可完成的核心任务，非阻塞知识列入待补清单；依赖该知识的任务保留未完成。
- 关键算子、反向传播与 single-head attention 独立实现后对照；样板代码可借助 AI，但必须能解释、修改和排错。
- 每次关键练习至少做一次“预测改动效果 → 运行 → 解释差异”；不以逐行重敲或看完视频作为验收。
- 本地可运行即可完成阶段交付；租 GPU、公开发布模型或应用时另行确认预算、数据与发布范围。

## Week 1 · micrograd（上）

- 学：Karpathy micrograd 前半，理解计算图与链式法则。
- 做：独立补全 Value 的加法、乘法反向传播；画计算图。
- 验收：脱稿解释两个节点的梯度，并手算一个例子的梯度。

## Week 2 · micrograd（下）+ 扩展

- 学：neuron / MLP / 训练循环。
- 做：实现 ReLU 或 pow / exp 中一个扩展，与 PyTorch autograd 对拍。
- 产出：长笔记 1《手写反向传播》，附一个排错案例。
- 验收：扩展梯度对拍通过，能解释误差；进行第一次范围复盘。

## Week 3 · bigram + 小应用起步

- 原理：makemore bigram；按需补 softmax、交叉熵与采样温度。
- 应用（3h）：用熟悉的 TypeScript 做“自然语言任务 → 固定 JSON”小工具；页面输入、服务端调用模型、展示结果，密钥只在服务端。
- 范围：只抽取标题、日期原文（不推断相对日期）和明确提到的优先级；缺失字段返回 null。暂不加登录、数据库或 Agent 框架。
- 验收：本地完成一次真实端到端调用；能讲清温度对输出的影响。

## Week 4 · MLP + 最小评测

- 原理：makemore MLP，理解 embedding 与 train/validation loss；初始化和归一化按需选学。
- 应用（3h）：固定 JSON schema，检查输出字段；建立约 20 条开发用样例，覆盖缺字段、歧义与无关输入。
- 验收：报告 schema 合法率、字段准确率与失败样例；服务端错误可在界面识别；复盘并删减选学项。

## Week 5 · single-head attention + 错误处理

- 原理：学习 Q/K/V 与 causal mask；不看答案实现 single-head attention，再对照课程。
- 应用（3h）：处理超时、无效 JSON 和模型调用失败；记录请求耗时与错误类别，不默认记录完整用户输入。
- 验收：解释缩放因子与 mask；通过小输入验证维度及未来位置被遮蔽；演示一个失败请求的处理。

## Week 6 · 最小 GPT + 可重复运行

- 原理：补 MultiHead、Block 与训练循环，组织为可运行的手写 GPT；不要求训练出优秀文本。
- 应用（3h）：一条命令执行开发样例推理与评分，固定模型、提示词版本和评分口径。
- 验收：GPT 前向与反向能运行；应用有环境变量示例和启动说明；进行范围复盘。

## Week 7 · 训练与解释 + 应用 baseline

- 原理：小规模字符级语料训练，记录训练/验证 loss 与生成样例。
- 产出：长笔记 2《从零手写一个 GPT》，说明模型限制；官方 nanoGPT 对比仅为选学。
- 应用（3h）：保存当前 baseline、耗时、失败分类与复现命令。
- 验收：能解释过拟合信号，完成一次预测后验证的实验；小应用可本地演示。

## Week 8 · HuggingFace + 改进决策

- 原理与实验：按任务学习 tokenizer / datasets / 模型加载；评估小应用的失败主要来自提示词、输出约束、数据还是模型能力。
- 数据：建立验证集和锁定测试集，合计约 50~100 条，注明各自数量；W4 的开发样例只作开发/验证，不冒充未见测试题。
- 应用（3h）：用验证集比较提示词或输出约束改进，记录指标与版本。
- 验收：写明是否进入 LoRA 实验及理由；无适合微调的错误时，改走提示词/约束/数据改进路线。

## Week 9 · 数据与评测协议

- 实验：若做 LoRA，构造并清洗适量训练数据，先小样本跑通；不做 LoRA 则整理错误分类并确定一个改进变量。
- 划分：训练、验证、测试分离；按来源或模板分组切分并去重，避免改写样例跨集合泄漏。测试集不用于调参或选择方案。
- 应用（3h）：复用评分脚本，固定 schema 合法率、字段准确率的分母与缺失字段规则，同时记录耗时。
- 验收：一条命令完成推理与评分，数据来源和划分可追溯；只用公开、合成或获准数据。

## Week 10 · 有条件的 LoRA / 对照实验

- LoRA 路线：按模型文档学习 rank、alpha、target_modules；选择资源可承受的小模型，先做小规模训练并记录超参和日志。租 GPU 前确定预算上限与停止条件。
- 替代路线：比较 baseline 与一个提示词、输出约束或数据改进方案，保持其他条件一致。
- 应用（3h）：将选定方案接回原应用；若本地无法运行微调模型，保留独立离线评测并明确该限制。
- 验收：验证集结果可复现，记录失败或无提升的结果；不要求微调必然胜出。

## Week 11 · 锁定测试 + 交付说明

- 实验：锁定方案后运行最终测试，比较 baseline 与最终方案；列出样本数、指标、耗时和失败案例，小样本结果不泛化为普遍结论。
- 应用（3h）：整理环境、运行步骤、截图与已知限制，请他人或在干净环境按 README 验证；目标是依赖与凭据备齐后 10 分钟内启动。
- 验收：说明改进是否值得采用；测试失败后若继续调参，须将该集合视为验证数据，另留未见测试集。

## Week 12 · 复盘与 Phase 2

- 写：长笔记 3《从 baseline 到改进：数据、评测与取舍》；LoRA 做了再写微调部分。
- 整理 repo-governance 已有材料为评测案例：任务集、成功判据、失败类型与版本对比；只引用已有证据，缺项标待补，不扩张成新项目。
- 复盘：检查两个手写实现、小应用、实验报告与三篇笔记；未达标项保留未完成，不用发布动作代替验收。
- 排 Phase 2：围绕同一应用逐步补 RAG / Workflow / Agent、链路追踪与部署，根据实际失败决定加入哪种能力。

## 每周固定仪式

- 周日晚在复盘预算内用 30 分钟收尾笔记、更新真实进度、写下周三件事；剩余时间处理必要文档。
- 每两周检查工时与阻塞，列出本轮删除的选学项和待补知识。
- 小步提交：有意义的最小单元一个 commit。
- 项目说明：是什么 / 为什么 / 效果与指标 / 怎么跑 / 失败案例与限制。
- wiki 按规则摄入与维护，学习进度仍以本计划和 weeks 笔记为准。
