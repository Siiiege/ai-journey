# wiki 维护规则（Agent 读）

这个 wiki 是 `docs/` 与 `weeks/` 的**编译层**：agent 写，人读。源文件是事实源头，wiki 只放摘要、交叉引用和状态快照。

## 黄金规则

1. **不复制原文**。页面写提炼后的要点 + 链接回源文件；超过 3 句的照抄就是事故。
2. **进度状态不双写**。学习进度的唯一事实源是 `docs/phase1-plan.md` 的打勾和 `weeks/` 的笔记；wiki 页面里的「状态」行只是快照，必须标注快照日期，刷新只能发生在 LINT 时。
3. **每页开头标 Source**。写明编译自哪些文件；含推断或会话记忆的内容单独标 `（推断）` 或 `（会话记录 YYYY-MM-DD）`。
4. 知识页（如反向传播）里，**尚未学到的结论不要编造成已掌握**——立骨架，标「待回填」，等 INGEST 用真实笔记填充。

## 目录结构

```
wiki/
  AGENTS.md   本规则
  index.md    内容目录（入口）
  log.md      时间线，append-only
  pages/      页面。文件名用小写连字符，一个实体/概念一页
```

## INGEST（摄入）

触发：新周记入库、新作品发布、docs/ 有实质更新。

1. 通读新源文件和它影响的已有页面。
2. 更新所有相关页面（一篇周记通常影响 2~4 页），不是只加一页。
3. `index.md` 补目录条目，`log.md` 追加一行：`YYYY-MM-DD 摄入 <源>，更新 <页面列表>`。

## QUERY（查询）

被问「学到哪了 / 接下来学什么 / 某概念是什么」时：先查 `index.md` 定位页面，读完再答，答案引用页面与源文件。有价值的综合回答归档成新页（先查重）。

## LINT（维护）

触发：每周日固定仪式（见 `docs/phase1-plan.md` 末尾）、每月末、或 INGEST 时顺带。

逐项检查：

1. **快照过期**：`phase1-plan.md` 的打勾变了 → 刷新对应页面「状态」行的日期与内容。
2. **双写漂移**：页面里出现与源文件重复维护的状态清单 → 删掉，改回一行快照 + 链接。
3. **孤儿页面**：没有任何页面链到它、也不在 index 里 → 补链或删除。
4. **坏链**：逐页点一遍相对链接（`../..` 指向源文件，`./` 指向同目录页面）。
5. **待回填堆积**：连续两次 LINT 仍标「待回填」的段落 → 在 log.md 记一条提醒。

完成后 `log.md` 追加：`YYYY-MM-DD LINT：<结果摘要>`。
